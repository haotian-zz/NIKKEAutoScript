# 设施来源、巡检与受阻恢复

用户要求：优先复用 PR #303 的现成设施数据；没有数据时拖动游戏场景，从右上角逐屏扫描机关和传送点。记住已尝试对象，受阻后依次尝试，检查道路是否实际打开；已解锁且能帮助到达目标的传送点可以优先使用。

## 代码落点与当前边界

- `facility_memory.py`：实例／章节／难度／底图 SHA 隔离的持久目录。保存设施语义、静态地图点、场景关键帧引用、尝试与结果。不是新的地面寻路器。
- `facility_survey.py`：独立设施巡检。复用 `ChapterSweep` 的正式镜头输入、避让小队、边界及重叠验证；看见敌人不提前结束。先向右、向上确认边界，再逐行蛇形扫描。
- `structures.py`：加载经过现有 `chapter_map` 和 `validate_annotations` 校验的外部数据，登记当前两帧设施；同一受阻任务中已试过的设施不再次点击。没有当前可尝试设施时，当前执行至多发起一次设施巡检。
- `visible_story.py`：设施目录延迟建立，普通寻敌不额外加载关键帧；历史敌人身份与设施身份分开。

场景检测仍使用已做生产同口径对比的检测器。本轮改进的是设施身份、记忆和探索，不把检测器类别 start/end 当成传送方向。

| 数据来源 | 坐标依据 | 能证明什么 | 不能直接证明什么 |
| --- | --- | --- | --- |
| 外部标注 | 已校验章节底图像素 | 提供设施位置、显式连接方向 | 当前账号激活状态、当前道路已打开 |
| 场景扫描 | 当前真实画面与静态关键帧 | 设施被看见、同一设施的几何关联、双帧外观状态 | 章节底图坐标、入口出口配对、完整检出率 |
| 操作前后小地图定位 | 真实圆环、独立通过配准的双帧 | 实测小队位置及位移 | 仅凭位移判定传送或机关因果关系 |

两种来源进入同一目录，但目前没有可靠的“扫描点→底图点”自动绑定。不会直接混用两种像素坐标，也不会伪装成已经完成全局设施导航。外部地图点暂未接入当前主线直接执行链；PR 的地图规划代码仍保留在仓库。

## 身份和状态约束

1. 所有落点来自新鲜双帧检测；历史坐标仅用于身份与规划候选。
2. 机关 off/on 可以是同一对象；平台 start/end 外观变化也不能换编号。光幕和立柱保留独立语义。
3. 几何关联要求既有背景配准通过，两边内点凸包支持、15px距离、12px次选间隔且不发生多对一。
4. 凸包外推只可否决重复建档，不能授予关联或点击。记录为 `identity_outside_support`，留待换角度补查。
5. 点击前落盘 `attempted`；取消、超时及移动均不变成 `activated`。机关只在双帧实测 on 后记录 `observed_on`。
6. “尝试过”按受阻任务及已验证状态版本隔离。已知机关从 off 变为 on 时，旧的失败尝试可以进入新一轮；仅拖镜头、位移或日志增加不能重置。
7. 传送点不是永久一次性对象。未知连接不配对，不从 start/end 标签或同区域位移推断双向连接。

目录只含本地数据，位于 `log/campaign/facilities/<scope hash>/`，不修改资源仓库。最多64个关键帧、256个设施，每个设施至多32条尝试；容量满时停止而不丢弃已尝试身份。关键帧只保存数值特征，禁止 pickle，不保留原始截图在目录内存。任务进程退出后应释放描述子及模型进程；另以独立资源观察器验证。

## 实验矩阵和通过标准

| 实验 | 通过标准 | 不通过时下一步 |
| --- | --- | --- |
| 跨视角身份／重启记忆 | 实际移动镜头及重启后不重复尝试同一设施；不同近邻不合并 | 查几何支撑、视差和状态外观，禁止靠新编号绕过 |
| 完整镜头巡检 | 两轴有实际响应；右、上、左右行边缘、下边缘有证据；相邻重叠通过 | 保留 partial 和原图；形成新假设后才重试 |
| 不同地貌 | 沙漠／城市／丛林分别保留独立连续序列，记录纹理不足、漏检、误检和关联失败 | 优先补自动采集的真实困难序列，再决定检测或匹配模型 |
| 机关闭环 | 两帧 off→操作→两帧同一机关 on；回查原受阻处及目标可达结果 | 区分没到达、没触发、开了其他门、前置未满足 |
| 传送闭环 | 实际入口、操作前后真实小队位置、出口实测身份和方向相互支持 | 保留未知出口或普通步行，禁止自动生成连接 |
| 退出释放 | 任务／推理子进程退出，至少30秒冷却，回到既有GUI基线；观察器也退出 | 找存活子进程和持有者，运行峰值大不直接认定泄漏 |

扫描的 `camera_coverage_verified` 只表示镜头条带检查通过，`detection_complete` 始终为 false。它不是“所有机关已检出”，也不是“本章全清”。180秒默认巡检预算，不因发现敌人或新识别日志续期。

2026-10-21 首轮实机：两次镜头动作、四次双帧采样后因背景内点分布不足停止，保存 partial。目录有五条候选，尚不能视为五个独立实体。未点击设施、未增加胜利；鼠标和720×1280窗口恢复，任务进程退出。已保存原始证据并在Windows相同OpenCV版本离线复现。

针对该失败帧的静态特征采样对照：原1800上限／对比度0.04得到1022／983特征，几何覆盖不通过，约399ms；3000／0.02得到2002／1977特征，通过同一几何检查，约415ms；4000／0.01也通过，约417ms。本轮选择较小的3000／0.02，不修改配准或覆盖保护阈值。此结果只针对一组失败帧，不能称为跨章节性能结论。独立实机第二轮继续验证。

第二轮八次镜头动作后因地图边缘横向手势实际斜向滑动而停止，矩形条带前提不成立。设施采集另允许有几何支持的斜向运动继续，但一直记录覆盖存疑；清怪检查默认规则不变。第三轮六次动作后在头像未确认时停止，33组累计双帧采样仍未确认全图覆盖，0设施点击、0新增胜利。

头像末帧被小地图遮挡；新增 `vision/minimap_occlusion.py` 临时收起遮挡，用原头像规则双帧读取，随后恢复。首次UI实测暴露关闭态“图钉”被旧放大镜规则误拒绝，已新增独立图钉识别并接入观察器及野外判断；它的小孔不能套用放大镜80px²门槛。支持进入时地图已关闭，避免遗漏恢复。只有实际双帧头像和恢复均验证，才能让后续镜头动作继续；仍不从头像构造地面坐标。

相关检查覆盖116个不同场景：前批115通过，最后遮挡分支改动定向五项通过（替换原四项），不宣称最后把所有116重新跑了一遍。前三轮任务退出后资源均回到约1.138GB常驻GUI基线，不代表已验证整GUI关闭浸泡。

遮挡补查v3实机28.453秒：初始关闭路径和完整收起／双帧头像／恢复路径均通过，圆心(86,314)，最终紧凑地图、鼠标释放及竖屏恢复通过，0场景输入。该项只验证读取与恢复，尚未做修复后全章设施扫描，不把它算作通行或胜利。

## 下一段实现顺序

1. 先完成实机完整扫描、跨视角唯一身份及可恢复的覆盖记录，处理纹理不足和离屏小队识别。
2. 将扫描设施绑定到可靠的地图／局部拓扑坐标。关卡号与画面中心均不能代替定位；不同地貌不使用主色阈值假设。
3. 接入“选择未试机关→找到新鲜可见目标→原生寻路交互→机关状态复核→回查原受阻处”的状态机。当前两次设施／四次普通侦察预算仍保留，尚不能声称已支持遍历全章所有机关。
4. 传送点只在入口出口与方向验证后接入策略；已有标注优先作候选，实际可达性和收益决定是否使用，也覆盖同连通区域的捷径。
5. 将设施状态和经过验证的通行结果接回 PR 的 RunState／CutRoads／route planning，修正 PR 点击即标 on、缺少箭头时画面中心兜底等不合当前要求的行为，再进行连续主线实测。

完整实机记录和后续交接见协作仓库 `2game-helper/docs/NIKKE_SESSION_HANDOFF.md` 与当日视觉方案、基准记录；这些文件保存真实胜利计数，扫描不增加计数。
