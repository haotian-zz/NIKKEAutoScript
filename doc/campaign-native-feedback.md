RTX4090其他游戏运行时，完整15片场景CPU4线程P50约621ms；生产Python3.9私有CUDA初测309ms、两轮各20次复测214/218ms；整帧隔离服务复测283/230ms。选择直接CUDA，以当前可部署、通过关键对象核验的配置整体耗时为准；不以网络单次前向或某次最好值选型。

## 配置与兼容

默认仍是CPU，配置仅AutoPush读取，文件不入Git：

```json
{
  "backend": "cuda",
  "threads": 4,
  "benchmark_passed": true,
  "model_sha256": "de783a17cf04628644eccc510d5bb071d3bdbaaa880da76d3436ad26d23362fd"
}
```

路径为`data/campaign_detector.json`。CUDA依赖固定为`data/vision_runtime/ort39-gpu`，DLL目录固定为`data/vision_runtime/venv/Lib/site-packages/torch/lib`，均为本机实验环境，不自动下载，不修改toolkit已装依赖或系统PATH。只在进程尚未载入其他ORT时加载私有包；缺依赖或CUDA不可用保留CPU。日志记录实际providers，不能仅凭配置声称CUDA已生效。

`AutoPush.runtime_ready()`必须先配置后实例化检测器，避免CPU二进制已载入后热替换。进程内共享模型会话，CPU线程1～8可配置，默认4；线程更多本次反而变慢。其他实例使用CPU。隔离HTTP客户端/worker保留作性能实验，当前选型不启动服务，界面与游戏输入仍由正式会话执行。

## 点击后的状态

稳定识别脚圈后直接点击，普通道路交给游戏原生寻路；不需要先分割地面、识别深坑或建立整章道路图。新增`vision/native_motion.py`比较相邻帧，双向光流拟合背景变化，扣除镜头对小队箭头的影响。缺箭头、纹理或局部几何支持均为unknown，不能假定人物位于画面中心。

- `moving`：背景补偿后残差≥12客户区像素，可延长等待，但本次最多60秒。
- `stationary`：残差≤4像素；点击后留2秒响应，连续3次且跨2秒才报告`stalled`。
- `unknown`：打断静止序列；20秒没有可靠结果停止并留原图。
- 实际备战：优先退出移动观测，连续核对实际关卡，然后交给战斗闭环。

`stalled`只是本次点击的反馈，不等于道路不可达。观察簿记录最多8次未完成尝试，保留既有身份；真实胜利后允许重新观察受阻目标。镜头移动、点击设施和三帧停稳都不证明平台传送或战斗胜利。设施诊断仍有独立输入预算，不能无限重试。

## 箭头动画与独立静止证据

第二轮最终确认20-24、20-26、20-27、20-28、20-29、20-30六次胜利，任务为20-31后，箭头动画使逐帧残差在静止/未知之间交替而主动停止。失败原始序列来自`20261021_030216_937516`的77～83事件，x恒定、y约401.5～412.5；小地图圆心变化不足0.5px，轮廓变化近0。

新增`MinimapStability`只观察固定UI中的唯一精定位圆环与有二维转角的道路轮廓，不执行道路重建；与起始参考比较，不能把累计移动拆成小变化。少纹理直路、控件/圆环缺失、道路滚动、遮挡过多均unknown。独立UI可确认已标定的竖直箭头动画下小队静止；大于动画范围或明显横向的场景移动与UI冲突仍unknown。生产Python CPU回放在约9.12秒确认连续静止，原方案21.48秒后停止。尚待下一轮在线确认设施恢复结果。

设施等待共用该反馈：无可靠结果20秒、真实移动最多60秒，静止只记录`stationary_interaction_unconfirmed`，不是传送成功。数值解码兼容不同CPU上约1个FP32精度单位的Sigmoid负零，仍拒绝明显越界分数。相关Windows本阶段86项回归通过，与之前不重复项目合计105项；游戏测试和GPU计时等待重训结束。

## 自圈误检与大型入口

第二轮实际点击前原图表明，目标是小队自己的橙色圈，真正Boss入口漏检。因此该停滞不能作为平台缺口证据。前两轮实际共确认20-23至20-30八个不同普通关卡胜利，第三轮未新增胜利，因巡检位置未确认自动停止。不能报告整章全清或平台传送成功。

现在同一次8网格同时提取脚圈与箭头，不增加推理切片。唯一箭头还须真实模板精定位，其已有地面锚点位于某圈框内时排除歧义圈，证据记为`squad_overlap`；箭头缺失或不唯一不使用画面中心猜测。排除不等于已清除，相关区域仍从背景纹理中屏蔽角色动画。

大型入口由`vision/boss_ring.py`补充：固定骷髅二值图标的有限仿射IoU与局部发光椭圆环必须同时成立。门槛0.65/0.2分别是字形IoU与零均值相关，不是校准概率。没有骷髅不搜索圆环；不按地貌颜色、章节号或预设坐标生成落点。返回`kind=boss`仍不能代替实际备战编号，正式流程继续要求两帧稳定、原生点击寻路、身份核对和胜利结算。

同一失败遭遇的两视角，三个模型都漏Boss；新24帧回放15张完整入口检出14张，其余9张无输出。主要是同一Boss相关帧，不能宣称跨章准确率。415历史帧与59城市视频候选均无提案，但未完整标注，不能当作零误检测试。本阶段Windows109项相关回归通过，第四轮有界实机已发起，尚待结果。原图、训练权重及私有配置不入Git；二值小图为产品UI资源。
