# 执行简报与失败重试

在实例的「任务总览」查看最近执行卡片，或打开「执行记录」选择某一轮运行。记录保存在运行 NKAS 的机器上，关闭浏览器不会丢失。

调度器从一批到期任务开始执行，到队列处理完毕或中断，形成一份简报。常驻等待下一次日常不算仍在执行。此前没有结构化记录的旧日志不会自动补成简报。

## 看懂结果

| 状态 | 含义 |
| --- | --- |
| 已完成 | 已确认配置范围内的目标完成，例如免费次数为零，或可领取奖励已处理。 |
| 部分完成 | 有成功步骤，也有遗漏，或统计仅识别到部分项目。 |
| 失败 | 超时或异常导致未完成，可查看原因、日志与结束时截图。 |
| 待处理 | 需要先处理账号前置、编队或配置；战斗未通过也会单独说明。 |
| 正常跳过 | 已确认本次无需执行，例如准备期、没有对应活动功能或货币不足。 |
| 结果未确认 | 证据不足。正常返回、内部捕获异常或入口未识别，都不能直接等同于成功。 |
| 未执行 | 本轮计划中尚未开始的任务或子步骤。 |

正常跳过和已完成默认收起，先展示需要关注的项目。停用的任务、未到执行时间的周期任务不算本轮遗漏。已接入明确完成判断的日常模块会报告具体结果；尚未提供完成证据的旧模块保留为「结果未确认」。

## 补做未完成项

1. 简报结束后，默认选中允许安全重试的失败或部分完成项目。
2. 可以取消勾选、另选任务，或使用某行的「重试 / 检查并重试」。未解锁和未编队不会默认选中。
3. 重试使用当前保存的配置。任务运行中时，排在当前任务之后；实例原本停止时，仅执行所选重试任务，之后恢复停止状态。
4. 成功后更新同一份简报，显示「重试后完成」。详情里仍保留每次尝试的失败原因、日志和截图。

补做过程中若需要先登录，登录成功后继续原任务。中断的简报在全部任务恢复为已完成或正常跳过后改为「本轮已结束」；仍有失败或未执行项目时保留中断状态。

活动、派遣、商店、收获等组合任务记录子步骤。配置和游戏日相同时，已确认完成或无需执行的步骤沿用前次结果；未完成步骤重新执行。配置改变后重新检查，避免把旧配置的成功结果用于新目标。商品购买仍会检查游戏中当前可用商品。

招募、付费歼灭、送礼、装备强化和活动买票等存在重复消耗风险的情况，不提供盲目重放入口。先在游戏里核实结果，再按需要单独执行。通知任务的补做只核对当前开关，不补发消息：关闭时记正常跳过，启用时保留原通知送达情况未确认。停止或进程中断时，正在进行的操作标为「结果未确认」，不会自动假定没有发生。

本版按 NKAS 当前的 UTC+8、04:00 刷新规则划分游戏日，与 UTC 20:00 等价。美服每日刷新时间经用户确认是 UTC 20:00；洛杉矶夏令时为 13:00、冬令时为 12:00。跨日后按钮显示「按当前游戏日执行」，建立关联的新记录；旧简报保持原结果。排队期间跨过刷新点的旧重试不会继续写回昨天的记录。

## 数据与构建

- 数据库：`data/executions/reports.sqlite3`，使用 SQLite WAL 协调界面进程和执行进程。
- 结束截图：`data/executions/screenshots/`；详情保留最近的相关日志，并隐藏可能包含凭据的日志行。
- `data/` 不纳入 Git。请勿把个人简报数据库和截图提交到仓库。
- 前端沿用 `webui/` 的 Vue 界面与主题。修改后执行 `yarn run typecheck` 和 `yarn run build`。
- 可通过 `NKAS_WEBUI_DIST` 指向单独构建的前端目录，避免把部署产物写入源码。未设置时仍使用 `webui/dist`。
- 回归检查：`python -m unittest discover -s tests -p "test_execution*.py"`。测试使用临时数据库，不操作游戏。

活动推图、加成编队与超时设置见[活动流程说明](event-progression.zh-CN.md)。

执行记录接口位于 `/api/{实例名}/executions`；重试接口为 `POST /api/{实例名}/executions/{记录ID}/retry`。重试需要所选任务、报告 revision 和唯一 request_id，由服务器校验当前状态并去重，不会强制启用任务或移动原计划时间。

默认启动检查及单人突击空队处理见[启动与突击说明](startup-and-solo-raid.zh-CN.md)。
