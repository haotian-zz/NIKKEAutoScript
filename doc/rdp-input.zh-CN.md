# Windows 远程桌面鼠标输入

在 NIKKE 的 Windows 远程桌面会话中，将 PC 输入方案设置为 `driver`。脚本会根据运行进程所属会话选择输入通道：控制台沿用虚拟 HID；RDP 使用已经安装的 Interception 驱动中的 RDP 鼠标。

这需要目标 Windows 已有可用的 Interception 鼠标驱动和足够权限。此功能不会自动安装 Interception。普通窗口消息或 `SendInput` 在部分游戏会话中只能移动光标，不能可靠点击。

首次打开通道时，脚本枚举 `TS_INPT\TS_MOU`，发送没有位移、没有按键的标记，再从本会话的 RAWINPUT 消息确认所属设备。设备号不写死，也不需要用户手动移动鼠标绑定。绑定不到唯一设备时停止，不能改用其他会话鼠标或物理 HID；RDP 中也不会自动修复控制台驱动。

RDP 鼠标报告使用桌面绝对坐标，点击、拖动和滚轮都通过同一个会话通道。继续使用现有输入互斥与退出释放逻辑。

2026-10-20 已在 2560×1440 的 NIKKE 会话、720×1280 游戏客户区实测：外层 RDP 客户端保持最小化，脚本可进入活动、切换难度、滚动并处理结算页面。缩放客户端显示不改变游戏截图坐标；关闭连接或使 Windows 会话注销不等同于最小化，本次未验证这些状态。

会话识别、设备筛选、绑定不唯一、会话变化以及按钮和滚轮报告均有 Windows 回归检查。安装目录如有自定义主线或资源功能，应按文件合并补丁，保留原有实现。

执行记录中的单项运行会先绑定所选任务的配置；不会使用通用 NKAS 配置代替派遣等任务的开关或更新时间。前哨建筑详情若未匹配到已知建筑页，导航会先识别成对的关闭和进入控件，关闭详情后继续返回大厅。
