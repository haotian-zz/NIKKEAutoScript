# 默认启动检查与单人突击自动编队

## 点击开始后的行为

所有 NKAS 实例默认共享启动检查，无需逐个实例添加配置，不增加任务标签或开关。

- 调度器点击开始后，即使当前没有到期任务，也先检查游戏，再按原计划等待。
- 游戏未运行时，通过已配置启动器拉起游戏，处理标题页进入、公告等登录流程，确认到达大厅。
- 游戏正在运行时继续使用原进程；已在标题页则完成登录。已有游戏页面不因检查而强制重启。
- 单项执行和执行简报补做也使用同样检查，登录后继续原任务。
- 通知、妮游社等不依赖游戏的独立任务保持独立，不为它们拉起游戏。

输入仍遵守原有串行和鼠标互斥规则。登录每次等待最多 5 分钟，30 秒先保存诊断截图；既有登录恢复最多三次。账号验证、维护等情况沿用原有明确退出和提示。启动器路径及登录状态仍需正确配置。

这是执行入口的内部检查，不建立一个名为 Startup 的可见调度任务，也不修改正常日常的下次运行时间。

## 单人突击没有编队时

普通模式优先使用已有保存队伍；当前队伍为空时进入突击编队页，点击游戏「自动编队」，保存并确认回到突击面板后才继续入场。仍可入场的队伍不清空、不重排。若全部预设均无法入场，最后一组的五名角色又全部明确显示「无法选择」，则在确认本轮仍有出战机会后重建这一组，再使用未出战角色自动编队。只有实际出战消耗机会后才允许再次重建，防止按钮失效时重复改队。挑战模式也接入空队处理。

角色能否上场由游戏的编队规则判定，包括本轮已出战限制。自动编队没有可用角色时返回并尝试下一组；每组每轮只尝试一次自动编队，避免无角色时重复打开编辑器。不会为此购买次数或放弃当前突击。

注意两种计数：

- 每日突击次数：一次完整突击的入场机会。
- 突击面板的 `2/5`：当前这一轮还可出战两支队伍；三支队伍出战不等于消耗三次每日机会。

编队等待最多 45 秒，15 秒保存诊断截图；普通模式每组入场等待最多 10 秒，页面切换最多 45 秒。一轮战斗总等待最多 20 分钟，调度与补做的整个任务最多 60 分钟，以容纳多轮及五队实战；长战斗仍会留下诊断截图。当前实现使用 720×1280 的现有编队布局和资源，实机验证语言为简体中文。

已补充从编队页、未完成突击、进行中的战斗及结算页接续；已识别“挑战结束，纪录/记录已被重置”的确认提示，确认后结束当前任务并保留剩余每日机会；没有可继续队伍、五次出战耗尽但未确认击败 Boss、或结算仍有 Boss 血量时，报告待处理并保留剩余每日次数。消化次数成功不等于取得最高战斗奖励。补做中的恢复请求不强制启用或改动其他任务的排期。

## 回归检查

```sh
python -m unittest discover -s tests -p 'test_startup_preflight.py'
python -m unittest discover -s tests -p 'test_solo_raid_formation.py'
```

相关入口、简报及鼠标生命周期还应运行 `test_execution*.py` 和 `test_driver_control_lifecycle.py`。隔离测试不消耗游戏次数，不能代替目标账号的冷启动、热启动和空队入场实测。
